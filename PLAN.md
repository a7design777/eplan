# eplan — план і структура

Планувальник маршрутів для електромобілів по Європі. Деплой: Cloudflare Worker → **e.car-ua.com**.
Правила роботи — [CLAUDE.md](CLAUDE.md).

## Що робить застосунок

Користувач задає старт, фініш і проміжні точки, обирає авто, стартовий і цільовий заряд, фільтрує конектори/мережі/безкоштовні зарядки — і отримує:
- маршрут із зупинками на зарядку та часом кожної зупинки;
- загальний час у дорозі (їзда + зарядки) і кілометраж;
- попередження про платні дороги з альтернативним безкоштовним маршрутом;
- кнопки «відкрити у Waze / Google Maps» для маршруту і для кожної зарядки;
- збереження маршрутів в акаунті (email+пароль).

## Структура

```
eplan/
  CLAUDE.md                 # правила — читати перед змінами
  PLAN.md                   # цей файл — оновлювати після кожного етапу
  wrangler.jsonc            # Worker, assets, D1, KV, cron
  migrations/               # SQL-міграції D1
  data/vehicles.json        # сід ~30 моделей EV
  src/                      # backend (Hono на Worker)
    index.ts                # монтує /api/*, роздає static assets
    auth/                   # реєстрація, логін, сесії, requireAuth
    routing/
      valhalla.ts           # клієнт Valhalla: throttle + KV-кеш (єдина точка виходу)
      consumption.ts        # модель споживання: швидкість, підйом, температура
      charge-curve.ts       # інтегрування кривої зарядки → час зупинки
      planner.ts            # підбір зарядних зупинок (ядро)
      tolls.ts              # детекція платних ділянок + альтернатива
    stations/
      query.ts              # вибірка станцій у коридорі маршруту (geohash)
      import.ts             # cron-імпорт з OpenChargeMap
  web/                      # frontend (Vite + React + MapLibre)
```

**D1**: `users`, `sessions`, `saved_routes`, `stations`, `networks`, `connector_types`.
**KV**: кеш Valhalla (TTL 7 днів), кеш геокодування.

**Індексація станцій**: колонка geohash-префікса (7 символів) з індексом. Вибірка «станції в коридорі» = набір префіксів уздовж полілінії → один запит `WHERE geohash_prefix IN (...)`. Без цього D1 робить full scan на ~150k рядків при кожному плануванні.

## Алгоритм планування (`src/routing/planner.ts`)

1. Базовий маршрут через Valhalla `/route` з `elevation_interval`.
2. Симуляція споживання вздовж полілінії: базове Wh/km × коефіцієнти швидкості (квадратично від ~90 км/год), підйому (потенційна енергія + рекуперація з втратами), температури → крива SoC по дистанції.
3. Жадібний підбір зупинок: іти вперед, поки SoC не впаде до резерву (за замовч. 10%); шукати кандидатів у коридорі ~5 км серед досяжних; скоринг за потужністю, довжиною об'їзду, фільтрами користувача, кількістю портів.
4. Час зарядки: інтегрувати криву від SoC прибуття до SoC, потрібного щоб дістатись наступної точки з резервом (не «до 80%» наосліп) + ~5 хв на під'їзд і підключення.
5. Перерахунок маршруту з зупинками як via-точками (справжні об'їзди), за потреби один повтор кроків 2–4.
6. Врахувати цільовий SoC на фініші — остання зарядка може бути довшою.

**Платні дороги**: другий запит із `exclude_tolls: true`. Якщо основний маршрут має платні ділянки — показати обидва варіанти з різницею в часі й км; для безплатного зарядки перераховуються заново. Показуємо *наявність* платних ділянок і країни, не суму (Valhalla тарифів не дає).

**Deep links**: Waze `waze.com/ul?ll=lat,lon&navigate=yes` (по одній точці — Waze не тримає multi-stop). Google Maps `google.com/maps/dir/?api=1&origin=…&destination=…&waypoints=a|b|c`, ліміт 9 проміжних — якщо зупинок більше, ріжемо на кілька посилань.

### Що перевірено вживу
- Берлін → Мюнхен, Kia EV6: 590 км, 2 зупинки, 40 хв зарядки, фініш 11 % — сходиться з ABRP.

- Auth: реєстрація, вхід, вихід, ізоляція між користувачами (чужий маршрут не читається й не видаляється).
- 62 юніт-тести, `tsc --noEmit` чистий.

### Блокери
1. **OCM_API_KEY** — без нього в БД лише dev-сід (`data/dev-stations.sql`, `data/dev-stations-es.sql`),
   тож будь-який маршрут поза цими коридорами буде «непроїзним». Отримати:
   openchargemap.org → my apps → Register An Application.
2. ~~`wrangler login`~~ — зроблено, ресурси створені, прод живий.

### Відомі обмеження моделі даних
- Конектор `type2` не розрізняє AC Type 2 (11–22 кВт) і Tesla DC Type 2. Для старих
  європейських Tesla (Model S/X до CCS-ретрофіту) це може дати хибні зупинки.
  Пом'якшено тим, що імпортуємо лише станції ≥50 кВт.

## Перевірка

- `npm test` — детерміновані тести `consumption.ts`, `charge-curve.ts`, `planner.ts` без мережі.
- Звірка трьох реальних маршрутів з abetterrouteplanner.com, розбіжність за кількістю зупинок і часом у межах ~15%:
  - Берлін → Мюнхен (просто, ~1 зупинка);
  - Варшава → Барселона (довгий, багато зупинок, платні дороги);
  - авто з малою батареєю (Zoe) — стрес-тест підбору.
- Візуальна перевірка dev-сервера: мапа рендериться, маркери на місцях, Waze/GMaps посилання ведуть на правильні координати.
- Auth: реєстрація → логін → збереження → вихід → вхід → маршрут на місці; чужий маршрут не читається.

## Відкриті питання

- Ціни на зарядку: OCM дає їх нерегулярно — спершу орієнтир за kWh.
- Суми платних доріг недоступні безкоштовно — показуємо лише наявність.
- Публічний Valhalla — demo-сервер під fair use. План Б при зростанні трафіку: свій Valhalla на VPS для Європи або OpenRouteService з ключем.
